Reading an Internet route

Border Gateway Protocol (BGP) is how independently managed networks exchange information about reachable blocks of IP addresses. An Autonomous System Number (ASN) identifies one of those networks. For a typical BGP route, the rightmost ASN in the AS path is the origin, while the earlier ASNs describe the route as seen by a collector peer.

For example, if two peers see the same prefix through different AS paths but those paths end at the same ASN, the observations show different routes to the same origin, not an origin change. If the origins differ, check more peers and timestamps before drawing a conclusion: multiple networks may legitimately originate the same prefix.

Public data sources

  • CAIDA AS Relationships: inferred customer–provider and peer-to-peer relationships between ASNs.
  • RouteViews: public BGP routing table snapshots and updates gathered from collector peers.
  • RIPE Routing Information Service (RIS): public BGP observations from a separate network of collectors.

How to compare observations

Compare the same IP prefix and time window across collectors. Record the collector and peer for each route, then distinguish changes in the origin ASN from changes elsewhere in the path. Use a dated CAIDA snapshot for context on adjacent ASNs.

Collectors see only the routes their peers share. An unobserved route is not proof of an outage, and a CAIDA relationship is an inference, not proof of a business agreement or the path packets actually took.
